# ADR 0001: статус позиции `failed` и `failed_count`

Статус: принят (Женя, Артас в чате; Лёша — фронтовая часть сделана в этом PR, посмотрит после демо).

## Контекст
Если классификация одной позиции падает, сейчас валится весь файл. Фронт не может показать «эта строка не обработана», `failed_count` всегда 0.

## Решение
- В `ItemStatus` добавляется `failed`. Позиция получает его, если её классификация упала. Код, уверенность и кандидаты пустые.
- Задание при частичном падении остаётся `done`; воркер считает `failed_count`. `failed` у задания — только если упал весь файл.
- Новое необязательное поле `failure_reason` (до 255 символов) — причина для таблицы.
- Фильтр `GET /jobs/{id}/items?status=failed` работает через существующий параметр `status`.
- Миграция `0003` добавляет `failure_reason`; статус — строка в существующем поле, миграция не нужна.

## Последствия
- `docs/api/openapi.yaml` перегенерирован, копия `frontend/openapi.yaml` синхронизирована, `schema.d.ts` пересобран.
- Фронт: `failed` — красный тег (`error`), подпись «Не обработана».

## Альтернатива
Оставить упавшие позиции `needs_review` с пустым кодом. Отклонено: пользователь не отличит «низкая уверенность» от «не обработано».
