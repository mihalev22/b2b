# Шаг 5 — поиск кандидатов и pgvector

## Роль
step5_match.py выполняет retrieval: ищет пять позиций по близости нейроэмбеддингов.
Это ещё не окончательный выбор кода; его проверяет шаг 6. Код кандидата всегда
приходит из каталога, не из генерации. Модуль сохраняет итоговые товары в БД.

## Структура и зависимости
psycopg2, Json/execute_batch, функции шагов 1/3/4, DATABASE_URL; вспомогательные
функции подключения/таблиц, класс FindKtru, функция save_products.
По умолчанию DSN postgresql://postgres:postgres@localhost:5432/ktru (только демо).

## Таблицы
- ktru_index_meta: единственная запись с fingerprint и dimension.
- ktru_candidates: code PRIMARY KEY, item JSONB, embedding vector.
- parsed_products: job_id UUID + row_id составной ключ, filename, item JSONB,
  embedding vector, embedding_model, created_at.
Тип vector без жёсткой размерности позволяет сменить модель; длина проверяется
перед поиском программно. Для больших каталогов нужен индекс/миграции.

## Функции и методы
### connect_database()
Соединение psycopg2 с connect_timeout=10. Вызывающий код закрывает соединение
в finally. Пароли не помещаются в SQL-строки/результаты.
### create_tables(connection)
Создаёт extension vector и три таблицы IF NOT EXISTS. Требует права на extension.
Не выполняет автоматическую миграцию уже существующих старых таблиц.
### FindKtru.__init__()
Ставит ready=False, dimension=None, catalog_count=0. Не вызывает нейросеть/БД
при импорте API — сервер может запуститься для /extract без каталога.
### FindKtru.prepare()
Читает активные позиции каталога; получает /api/show модели; считает SHA256
по каталогу, модели, model_info, details, modelfile. Открывает транзакцию и берёт
pg_advisory_xact_lock(742618), чтобы два построения не конфликтовали.
Если fingerprint совпадает, переиспользует размерность/сохранённые векторы.
Иначе объединяет name/description/attributes, вызывает to_vectors, заменяет
кандидатов и метаданные атомарно. Затем ready=True и catalog_count.
Неудачная транзакция откатывается, соединение закрывается.
### FindKtru.search(vectors, limit=5)
Готовит индекс при необходимости; проверяет размерности. Для каждого запроса
SQL ORDER BY embedding <=> query LIMIT limit; similarity=1-cosine_distance.
Запрос параметризован. Возвращает список списков dict-кандидатов с similarity.
Это точный перебор, не HNSW; similarity не вероятность правильности.
### FindKtru.top5(text, brand='', model='')
Удобная совместимая обёртка для одного текста; brand/model отдельным бонусом
не используются. Передавайте полное product_text, чтобы не потерять атрибуты.
### save_products(job_id, filename, products, vectors)
Проверяет одинаковое количество объектов/векторов; транзакционно записывает
результаты execute_batch. При ошибке не остаётся частично записанного задания.
Не делает upsert: повтор UUID/row_id приводит к ошибке, а не тихой перезаписи.

## Поддержка и производительность
После смены каталога/модели перезапустите процесс. ready кешируется в памяти,
динамического обновления нет. fingerprint включает modelfile, но сравнение кода
формирования описания требует ручного пересоздания индекса. Для крупного каталога
нужны HNSW с правильной размерностью, пакетное построение без хранения всех векторов
в RAM и измерение recall/latency. Долгая генерация в prepare держит транзакцию,
для production выделите предварительное построение. Не используйте точность
на пяти тестовых строках как доказательство качества всего КТРУ.
