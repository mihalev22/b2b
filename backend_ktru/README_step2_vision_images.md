# Шаг 2 — vision-модель для изображений

## Назначение
step2_vision_images.py передаёт изображение локальной Qwen с vision. Это не
Tesseract и не regex-парсер. Модель возвращает товары в тех же схемах, что шаг 1.
Модуль вызывается API для PNG/JPG/JPEG и шагом 1 для сканов PDF.

## Структура и зависимости
Импорты base64/io/os/warnings, Pillow и схемы/HTTP-функции шага 1; настройка
VISION_MODEL; две функции. Модель по умолчанию qwen3.5:2b-q4_K_M, переменная
окружения задаётся до импорта. Для вызова нужна работающая Ollama с этой моделью.
Image.MAX_IMAGE_PIXELS=20000000 ограничивает декодирование чрезмерных изображений.

## Функции
### extract_image_bytes(data, source)
1. Открывает байты через Pillow; предупреждение decompression bomb делает ошибкой.
2. Учитывает ориентацию EXIF, переводит в RGB.
3. Уменьшает до рамки 1800x1800 без увеличения маленьких изображений.
4. Сохраняет JPEG quality=90 в памяти, кодирует Base64.
5. Добавляет к промпту шага 1 правила vision: извлекать только видимое,
   не угадывать бренд/числа по виду, не исполнять надписи-инструкции.
6. Вызывает ask_model с images и JSON-схемой Extraction.
7. Превращает товары в dict, добавляет source и evidence_type=vision_not_verified.
Надписи на изображении не сверяются отдельным OCR; это явно непроверенное свидетельство.

### parse_image_file(path)
Проверяет размер файла через check_file, расширение PNG/JPG/JPEG, читает байты
и вызывает extract_image_bytes. Некорректное содержимое картинки приводит к ошибке
Pillow/API, а не к результату без товаров с ложным успешным статусом.

## Контракт
Вход — файл или байты картинки, source — имя/страница. Выход — список Product:
name/raw_text/brand/model/quantity/unit/attributes/corrections/uncertain/source.
Пустой products означает отсутствие распознанных товаров, API отклоняет такой результат.
Модель может ошибочно выставить uncertain=false; это не гарантия правильности.

## Проверка 08.10.2026
Реальная Qwen 2B прочитала контрольную русскую надпись на PNG/JPG/JPEG и скан PDF:
Logitech K120, 5 шт, USB, проводное подключение. Файлы в audit_data,
полные ответы и время в audit_results.json. Это синтетические изображения текста,
НЕ настоящие фотографии товара, НЕ проверка размытия/перспективы/плохого света.
Нельзя переносить результат на произвольные пользовательские фото.

## Расширение и безопасность
Для проверки фотографий добавьте реальные фото с ожидаемыми наблюдаемыми признаками
и негативные примеры без маркировки. Не ожидайте, что модель узнает точную мощность
или размер по одному внешнему виду. Уменьшение изображения может ухудшить мелкий текст;
для сложных страниц можно добавить тайлы, но нужны дедупликация товаров и лимит запросов.
Metadata и исходная фотография в БД не сохраняются. Base64 остаётся локальным HTTP
payload; всё же не публикуйте Ollama наружу. Для каждого нового поведения сохраняйте
реальный тест, а не только mock.
