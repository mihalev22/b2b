# Шаг 1 — документы и текстовая нейросеть

## Ответственность и поток данных
`step1_text_docs.py` читает содержимое файла, сохраняет текст/таблицы и вызывает
Qwen через Ollama. Библиотеки не определяют характеристики товара: это делает
нейросеть. Выход — список словарей товаров, который передаётся в шаг 3.
Поддерживаются TXT, CSV, XLSX, DOCX, PPTX, PDF. Никакие команды из документов
не выполняются; формулы Excel не вычисляются.

## Структура файла
В начале находятся настройки OLLAMA_URL и TEXT_MODEL (окружение читается при
импорте). Затем Pydantic-схемы, системный промпт, HTTP-функции, проверки файлов,
читалки форматов, пакетная обработка и главный маршрутизатор.

### Схемы
- Attribute: name, value, unit — произвольная характеристика, без словаря синонимов.
- Product: name, raw_text, brand, model, quantity, unit, attributes, corrections,
  uncertain. Неизвестное количество — null; пустые строковые поля — пустая строка.
- Extraction: products, не более 100 товаров в одном ответе модели.
Поля ограничены длиной, лишние поля запрещены. Валидация JSON не гарантирует
истинность характеристик, только их структуру.

### Функции
- ollama_request(endpoint, payload): HTTP POST на Ollama, таймаут 240 с и connect
  10 с, trust_env=False. Ошибки HTTP/JSON преобразуются в RuntimeError.
- ask_model(system, data, schema, model=None, images=None): строит messages,
  прикладывает JSON Schema, отключает stream/thinking; temperature=0, num_ctx=8192,
  num_predict=4096, keep_alive=5m. Проверяет обрезанный ответ и JSON через Pydantic.
  Эту функцию используют также vision и проверка кодов.
- extract_products(text, source): запрашивает товары; проверяет, что raw_text
  встречается в источнике с нормализованными пробелами; добавляет source.
- decode_text(data): UTF-16 при BOM, иначе UTF-8-sig, иначе CP1251.
- check_file(path): проверяет наличие/20 МБ; для OOXML проверяет ZIP: не более
  10000 частей и 100 МБ распакованного содержимого. Не распаковывает ZIP на диск.
- read_document(path): возвращает пары (название раздела, текст). CSV сохраняет
  заголовки и разделители ячеек; XLSX читает все листы и сохраняет нули; DOCX —
  абзацы и таблицы в порядке; PPTX — текстовые фигуры и таблицы каждого слайда.
- extract_section(text, source): объединяет целые строки в блоки до 6000 символов
  и вызывает extract_products. Слишком длинная строка отклоняется, не обрезается.
- parse_text_file(path): публичная точка входа. Для PDF решает постранично:
  достаточный текст без изображений -> текстовая модель; иначе рендер -> шаг 2.
  PDF ограничен 40 страницами. Другие документы проходят через read_document.

## Использование
Из папки проекта: `python -c "from step1_text_docs import parse_text_file; print(parse_text_file('data/demo_spec.csv'))"`.
Для HTTP используйте POST /extract с multipart file; подробности запуска в README.md.
TEXT_MODEL по умолчанию qwen3.5:2b-q4_K_M. Смените окружение ДО запуска Python.

## Ограничения и доработка
Контекст между блоками может потеряться (включая заголовок таблицы). В DOCX/PPTX
вложенные фото/группы фигур не обработаны. Наличие логотипа в PDF переводит страницу
в vision, что медленнее. Цитата доказывает существование текста, не атрибута.
Для улучшения меняйте промпт и добавляйте размеченные тесты разных товаров;
не добавляйте regex-словари вместо нейросети. После изменений обязательно запускайте
unit-тесты и реальный аудит, проверяя не только имя, но числа и единицы.
