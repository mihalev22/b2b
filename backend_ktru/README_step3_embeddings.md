# Шаг 3 — нейроэмбеддинги

## Назначение и структура
step3_embeddings.py превращает описания товаров в числовые вектора через локальную
EmbeddingGemma. Файл содержит настройку EMBED_MODEL и три простые функции.
Зависимости: json/math/os и ollama_request шага 1. Нет NumPy, TF-IDF или обучаемого
словаря. API: POST /api/embed, официальный контракт https://docs.ollama.com/api/embed.

## Функции
### product_text(product)
Создаёт многострочное описание: название, непустые бренд/модель, затем каждая
характеристика в виде «имя: значение единица». Количество закупаемых штук намеренно
не включается: оно не определяет тип товара. Исходная цитата не включается.
Возвращает строку. Порядок характеристик сохраняется, поэтому для изменения порядка
или представления потребуется пересчитать каталог и проверить поиск.

### to_vectors(texts)
При пустом списке возвращает []. Остальное разбивает на пакеты по 32 строки.
Каждая строка должна быть непустой и не длиннее 6000 символов. Отправляет model,
input, truncate=false, keep_alive=5m. truncate=false запрещает незаметное обрезание
входа, но длинный по токенам текст всё равно может вызвать ошибку Ollama.
Проверяет число результатов, непустые вектора, конечность чисел, одинаковую
размерность внутри вызова, ненулевую норму. Нормирует каждый вектор:
v_normalized = v / sqrt(sum(v_i²)). Возвращает list[list[float]].
Размерность определяется моделью, а не константой 384; нет padding/обрезания.
Ошибки модели -> RuntimeError, ошибки входа -> ValueError.

### vector_sql(vector)
Сериализует список в JSON-строку для параметра SQL с приведением ::vector.
allow_nan=false отклоняет NaN/Infinity. Сам SQL выполняется в шаге 5 параметризованно.
Вызов vector_sql не сохраняет данные и не проверяет происхождение эмбеддинга.

Все конечны, норма 1. Повтор одинакового текста: cosine=1.0;

## Использование и расширение
`to_vectors(['Клавиатура USB', 'Бумага А4'])` требует заранее скачанной модели.
Если сменили EMBED_MODEL, пересоздайте индекс; нельзя сравнивать векторы разных
моделей даже при одинаковой длине. Настройки читаются при импорте.
Для полного поиска тестируйте recall@5 на размеченных товарах/кандидатах.
Нет проверки стабильности разных версий модели, токенизации и большого корпуса.
Для уменьшения нагрузки пакетные эмбеддинги вызываются до проверок генеративной
моделью; модель индекса кешируется в БД. Не сохраняйте выдуманные вектора как
«резерв», если Ollama недоступна: текущий код правильно сообщает ошибку.
