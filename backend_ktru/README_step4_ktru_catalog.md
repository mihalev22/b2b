# Шаг 4 — источник и проверка каталога КТРУ

## Что реализовано и что НЕ реализовано
step4_ktru_catalog.py импортирует нормализованный JSON-снимок. Он НЕ парсит HTML
страницы поиска ЕИС, не обходит CAPTCHA/авторизацию и не разбирает XML/ZIP выгрузки.
Нельзя назвать этот модуль автоматическим получением кодов с сайта.
Официальная страница: https://zakupki.gov.ru/epz/ktru/search/results.html.
В аудите 08.10.2026 локальный HTTPS-запрос завершился ошибкой сертификата;
внешний запрос — таймаутом. Это не доказательство глобальной недоступности ЕИС.
Проверенного снимка в проекте нет, реальная классификация официальных кодов не проверена.

## Проверка подключения (обновление)
Стартовый адрес теперь: https://zakupki.gov.ru/epz/ktru/start/startPage.html

`python step4_ktru_catalog.py --check`

eis_client() использует системный SSL-контекст и при необходимости добавляет
доверенный PEM CA из EIS_CA_BUNDLE. Сертификат нужно получить у администратора
сети/из проверенного источника, а не скачивать произвольный сертификат.
Пример PowerShell: `$env:EIS_CA_BUNDLE='C:\certs\trusted-ca.pem'`.
Проверка TLS никогда не отключается. Если сайт возвращает редирект/ошибку,
check_connection() сообщает это; успешный HTTP сам по себе не доказывает,
что каталог получен. В результате явно стоит catalog_downloaded=false.
refresh_catalog() также использует этот SSL-контекст, но по-прежнему требует JSON.
Для Docker сертификат требуется смонтировать внутрь контейнера и указать
EIS_CA_BUNDLE внутренним путём; Windows-путь внутри Linux-контейнера не работает.

Чтобы реализовать HTML-парсер, сначала сохраните в доступном браузере HTML страницы
результатов и одной карточки (с названием, кодом, статусом и характеристиками).
Передавайте только публичные данные, без cookies, токенов и персональных сведений.
По фактической разметке можно реализовать извлечение карточек и пагинацию;
нельзя заранее угадывать endpoint, селекторы и значение статуса active.
При доступной официальной выгрузке предпочтителен адаптер её подтверждённой схемы.

## Структура
Настройки LOCAL (KTRU_CATALOG) и OFFICIAL_CATALOG; Pydantic-схемы CatalogItem/Catalog;
функции проверки, чтения, импорта/обновления; CLI-блок __main__.
Зависимости: Pydantic, httpx, pathlib, datetime, urllib.parse, json, argparse.

## Контракт данных
Catalog: source_url, exported_at (YYYY-MM-DD), items (непустой список).
CatalogItem: code полного вида XX.XX.XX.XXX-XXXXXXXX, name, description,
attributes (dict[str,str]), source_url, active. description и attributes имеют
значения по умолчанию; остальные обязательны. Лишние поля запрещены.
Ссылка и код ОКПД2 не заменяют полноценную позицию КТРУ.
Схема может потребовать изменения после изучения реальной выгрузки ЕИС:
не обрезайте сложные характеристики ради прохождения валидации.

## Функции
- validate_catalog(data): валидирует JSON через Catalog; проверяет HTTPS и домен
  zakupki.gov.ru, отсутствие username; дата не в будущем; уникальные коды;
  минимум одна active позиция. Возвращает объект Catalog. Не доказывает,
  что код действительно существует, а ссылка соответствует карточке!
- load_catalog(): читает LOCAL, ограничивает 100 МБ, валидирует, возвращает
  список dict только активных позиций. Отсутствующий файл -> RuntimeError.
- import_catalog(source): принимает локальный JSON, проверяет размер/схему,
  создаёт папку, пишет временный .tmp, затем replace — старый снимок не заменяется
  непроверенным содержимым. Возвращает количество всех позиций.
- refresh_catalog(url): принимает ЯВНЫЙ JSON-ресурс HTTPS zakupki.gov.ru:443;
  ограничивает размер потока 100 МБ, запрещает редиректы, требует JSON content-type,
  валидирует и сохраняет атомарно. Подтверждённого подходящего endpoint сейчас нет.
  Обычная HTML-страница не пройдёт эту функцию, это ожидаемое поведение.
- CLI: `python step4_ktru_catalog.py "C:\exports\official_ktru.json"`
  вызывает import_catalog и печатает количество.

## Безопасность и дальнейшая работа
Не отключайте TLS verification ради прохождения проверки. При корпоративном TLS
настройте доверенный сертификат администратора. Не принимайте URL от произвольного
пользователя API. Для полноценного задания требуется легальная выгрузка ЕИС,
адаптер к её схеме, проверка актуальности, ссылка конкретной карточки для каждой
позиции и тесты с официальными примерами. Сохраните дату/происхождение снимка.
После импорта перезапустите backend: шаг 5 сверит fingerprint и пересчитает индекс.
