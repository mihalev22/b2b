# Уверенность в коде КТРУ

Владелец: Егор. Критерий приёмки №4 — у каждой позиции честный процент уверенности.

## Что значит «уверенность 85 %»

Среди всех позиций, которым система поставила 85 %, верный код должен оказаться примерно
у 85 из 100. Косинусная близость этим свойством не обладает: у хороших моделей эмбеддингов
она почти всегда лежит в узком диапазоне 0,7–0,9, и 0,83 не означает «83 % шанс». Поэтому
косинус переводится в вероятность моделью, обученной на размеченных позициях.

## Как считается

Для каждого из пяти кандидатов берутся три признака:

| Признак | Что это |
|---|---|
| `score` | косинусная близость запроса и позиции КТРУ |
| `margin` | насколько кандидат оторвался от ближайшего соседа |
| `lexical` | доля слов запроса, найденных в наименовании КТРУ (по первым 5 буквам) |

Из признаков получается оценка `z = bias + w·признаки`, а из оценок — проценты:

```
p_i = exp(z_i) / (1 + Σ exp(z_j))
```

Единица в знаменателе — вариант «верного кода среди пяти нет». Поэтому сумма процентов по
кандидатам не больше 100, а если все кандидаты слабые, у всех низкая уверенность.
Веса `w` и `bias` подбираются максимизацией правдоподобия на обучающей части выборки,
качество проверяется на отдельной части, которую модель не видела.

`needs_review = true`, если уверенность лучшего кандидата ниже порога высокой зоны.
Порог после калибровки может стать выше 85 (скрипт не опускает его ниже), поэтому
`needs_review` и зону считает только ml, а бэкенд и фронт берут их из ответа — см. ADR.

## Код

- `app/confidence.py` — расчёт в сервисе: `score_item(candidates, query, params)`,
  `params.for_model(имя_модели)` при старте, `params.thresholds()` для отдачи порогов
- `app/confidence_params.json` — веса, пороги зон и модель эмбеддингов; пока `calibrated: false`
- `calibration/calibrate.py` — подбор весов и отчёт
- `calibration/synthetic.py` — синтетическая выборка, пока нет настоящей

## Запуск

```bash
cd ml
pip install -r requirements-dev.txt
python -m pytest -q
python -m calibration.synthetic ../data/synthetic.jsonl --n 2000
python -m calibration.calibrate ../data/synthetic.jsonl --report calibration/report.md
python -m calibration.calibrate ../data/labeled.jsonl --save --embedding-model sergeyzh/BERTA
```

## Когда калибровать заново

Веса описывают, как ведёт себя `score` конкретного поиска, поэтому калибровка повторяется,
если меняется что-то из этого:

- модель эмбеддингов или её префиксы `query:` / `document:`;
- текст запроса (только наименование или наименование с характеристиками);
- способ подсчёта `score` у поиска (например, переход на гибридный поиск);
- число кандидатов.

Защита от забытой калибровки: в `confidence_params.json` записана модель, на которой
калибровали. Если сервис запущен с другой моделью, `for_model` пишет предупреждение в лог
и помечает уверенность как неоткалиброванную (`calibrated: false` в порогах).

План калибровок:

| Когда | На чём | Зачем |
|---|---|---|
| сейчас | синтетика | проверить механизм |
| 13–15 октября | рабочая выборка, базовая модель | первые настоящие цифры к демо 18.10 |
| 20–22 октября | рабочая выборка, итоговая модель | итоговые веса и пороги фронту к 22.10 |
| после 28 октября | отложенная тестовая выборка | один замер для отчёта, без подстройки |

## Формат размеченной выборки

Одна позиция на строку jsonl. Кандидаты — те, что вернул поиск, `true_code` — эталонный код:

```json
{"item_id": "17", "query": "Ноутбук Dell Latitude 5540 16 ГБ", "true_code": "26.20.11.110-00000009",
 "candidates": [{"ktru_code": "26.20.11.110-00000009", "ktru_name": "Машины вычислительные портативные", "score": 0.87}]}
```

## Результат на синтетике

600 проверочных позиций: ошибка калибровки ECE 0,158 → 0,047, среди позиций с уверенностью
от 85 % верных 95,6 %. Это проверка, что механизм работает, а не метрика проекта: настоящие
цифры будут после разметки (рабочая выборка от инженера БД — 13 октября).
